# Link outcomes to verdicts before memory pays

The agent-memory subsystem today cannot produce trading gains, because it never learns from outcomes. It is a per-ticker "last state" cache. Regex extraction turns committee verdicts, fills and trigger arms into atoms that overwrite each other. Retrieval is a SQL `LIKE` on the ticker. The result reaches exactly one place: the committee's LLM prompt. When that LLM call fails or is off, memory has zero effect on action, score, entry, stop or size. No table anywhere links a verdict to the P&L it caused. The one loop that does move numbers, `TradeLearner`, runs only on paper sells. It tunes up to nine parameters from the win rate of the last 20 trades. The richest outcome data in the system, shadow portfolios and the review tracker, is display-only. The published literature points the same way. Headline memory and reflection gains from FinMem, FinCon and TradingAgents decay 50–72% once tested after the model's training cutoff ([Profit Mirage](https://arxiv.org/html/2510.07920v1)). The most careful closed-loop ablation found memory return-neutral within noise ([CLQT](https://arxiv.org/pdf/2606.29771)). So the highest-value work is plumbing, not cleverer retrieval. In order: put a `report_id` and the initial 1R on every trigger, position and trade; label every decision with a settled, benchmark-relative outcome; make the learner statistically honest; and only then let shrunk, per-setup outcome numbers adjust prompts or thresholds. Proving any gain needs a paired memory-on/off A/B on the same candidates, scored on decision-level labels. Detecting +0.2R per decision takes roughly 180–440 paired decisions. A portfolio-level verdict would take years at this bot's trade rate.

## Memory today is a per-ticker cache that only an often-failing LLM reads

Three writers feed memory, all as fire-and-forget `asyncio.create_task` calls with no stored reference and no error callback. Every committee evaluation logs its transcript and verdict, including HOLD and SELL (`src/agents/committee.py:234-245`). Paper and live fills log trade events (`src/trading/paper.py:310-325, 430-446`; `src/trading/live.py:733-748, 1141-1157`). Armed triggers log trigger events (`paper.py:703-717`; `live.py:1305-1319`). Nothing is written when a trigger fills, cancels or expires. `AssetExtractor` turns this text into L1 atoms with regexes; its LLM branch is dead code because no caller passes `use_llm=True` (`src/memory/extractor.py:51, 266-296`). The key atoms are **`atom_verdict_{ticker}` and `atom_trade_{ticker}`, stored with `INSERT OR REPLACE`, so only the latest verdict and latest fill per ticker survive** (`extractor.py:208-246`; `src/memory/store.py:288-293`). A scratch simulation in the audit confirmed it: a BUY at 82 followed by a HOLD at 60 left a single atom reading "HOLD (Score: 60)". Realized P&L reaches L1 only as the first 160 characters of the SELL fill text (`extractor.py:243`).

Retrieval is keyword matching. `search_l1_atoms` ranks by exact subject match, then subject `LIKE`, then any match, then recency (`store.py:297-364`). The stored `confidence` column is never read in ranking, and no regime, sector, setup or outcome field exists in the atom schema. `ColdStartEngine` assembles a block of up to **2,400 characters**: portfolio status, a 30-day recap, a static persona with risk rules, the ticker's own L2 scenario, up to five L1 facts and two or three skills (`src/memory/cold_start.py:27-168`). It truncates from the end, so the ticker-specific sections are cut first while the boilerplate survives (`cold_start.py:151-152`). In the audit simulation, about 900 of 2,023 characters were static persona and rule text.

The loadout enters only the portfolio-manager `user_prompt`, and that prompt is sent only when `llm_client.has_active_key()` (`committee.py:59-67, 111-152`). The technical, fundamental and sentiment agents never see memory. `RiskManagerAgent` sets entry, stop, target and size deterministically, with no memory (`src/agents/risk_manager.py:20-38`). When the LLM returns nothing or malformed JSON, a weighted rules formula sets the score and memory is ignored (`committee.py:173-185`). That path is not rare in principle. The default `antigravity` provider shells out with a 90 s timeout and returns None on failure (`src/agents/base.py:120-133, 186-191`). A code comment records that it "hit the 90s timeout in ~98% of runs" for risk-level generation (`risk_manager.py:38`). That figure is for a different call; **the real share of `score_source == "llm"` committee verdicts is unmeasured**. It is recorded in `AnalysisReport.raw_signals`. Querying it on the production database is the cheapest first step, because it bounds how much any prompt-side memory change can ever matter. Even on the LLM path, a risk or sentiment veto caps the score at 55 (`committee.py:159-169`). Arming still requires a BUY, risk approval and a score at or above both `TRIGGER_MIN_SCORE` and `MIN_CONSENSUS_SCORE` (`src/trading/trigger_gate.py:87-122`).

Three other stores sit beside memory, and only one changes numbers.

| Component | What it holds | Changes a numeric decision? |
|---|---|---|
| Memory atoms and cold start (`src/memory/`) | Latest verdict, fill and trigger per ticker, plus boilerplate | No. It only nudges the LLM score, and only when the LLM answers |
| `TradeLearner` (`src/trading/learner.py`) | `TradeLesson` rows; calibrated `SystemConfig` | Yes: `MIN_CONSENSUS_SCORE`, `TRIGGER_MIN_SCORE`, ATR stop multiple, take-profit R:R, breakeven %, rules-path weights |
| `ShadowPortfolios` (`src/trading/shadow.py`) | Simulated outcomes of every verdict under preset rules | No. It reads `SystemConfig` and never writes it (`shadow.py:719`) |
| `review_tracker` (`src/data/review_tracker.py`) | Last week's picks vs the current price | No. Telegram and web display only |
| Code graph (`store.py:728-835`) | 15 symbols for coding agents | No. It is never in the loadout |

## No row anywhere links a verdict to its outcome

The schema cannot answer the basic learning question: "how did BUYs like this one turn out?" `Trade` has no foreign key to `AnalysisReport`, `OrderTrigger` or the opening BUY (`src/db/models.py:72-94`). The SELL row is written without a `consensus_score` (`paper.py:382-396`). `OrderTrigger.executed_trade_id` links a trigger to its BUY, but `create_price_trigger` receives no report id (`src/scheduler/jobs.py:347-359`; `models.py:187`). `Position` has no report or trigger id. Its `stop_loss_native` is mutated by breakeven and trailing logic, so **the initial risk unit (1R) is preserved nowhere** (`models.py:25-53`; `paper.py:490-500`). Without 1R, no outcome can be expressed as an R-multiple. And per-setup expectancy, the quantity every useful learning rule needs, cannot be computed.

The learner adds misattribution on top. The post-mortem takes the *newest* `AnalysisReport` for the ticker as the "original" report (`learner.py:66-69`). Held tickers are re-evaluated while open (`jobs.py:283-313`), so the score attached to a lesson can come from a report written after entry. It also takes the newest `Position` by ticker with no status or mode filter (`learner.py:48-51`). Post-mortem and automatic calibration are wired only into `PaperBroker.execute_sell` (`paper.py:450-457`). **`src/trading/live.py` contains no reference to `trade_learner`**, so live exits produce no lessons and no automatic calibration. `TradeLesson` has no `is_live` flag (`models.py:189-204`). The four newest lessons, paper and live mixed, are injected into every committee prompt (`learner.py:603-641`).

Two structural biases follow. First, outcomes exist only for fills, and fills come only from high-score BUY verdicts. Memory therefore never learns that a HOLD, a rejection or an expired trigger was a mistake. This is the selective-labels problem, where a decision-maker's own choices decide which cases get labeled ([Lakkaraju et al., KDD 2017](https://www.cs.cornell.edu/home/kleinber/kdd17-selective.pdf)). Expired and cancelled triggers are marked and dropped with no record of the later price path (`paper.py:896-925`; `live.py:1680-1682`). Second, the loadout re-feeds the bot's own previous verdict on the same ticker as a "fact" and as the matched L2 scenario (`cold_start.py:71-101`). Every new verdict is then logged back (`committee.py:234-243`). That is a self-anchoring loop, not learning.

The atoms are also partly wrong. Trigger prices are in native currency but always labelled € (`src/memory/client.py:125`; `extractor.py:121-122`). The rules transcript always says "AI Trigger armed", so a BUY deliberation creates a phantom `atom_trig_{ticker}_latest` even when arming is later skipped for cash, regime or share price (`committee.py:221`; `extractor.py:101`). A missing score defaults to 75 (`extractor.py:203-204`; `learner.py:70`). Memory-proxy traffic from coding agents writes into the same `trading-team` namespace the committee reads (`src/memory/proxy.py:46-47`). L0 grows without bound because `prune_and_compact` runs only on a manual HTTP call (`src/memory/routes.py:277-279`). The test suite would stay green if memory were deleted from the decision path: no test asserts that memory reaches the prompt, changes a verdict, or that live sells trigger post-mortems.

There is good news in this audit. `AnalysisReport` already stores action, score, levels and the full `raw_signals`, price included, for every evaluated candidate (`models.py:125-145`; `jobs.py:297-316`). `OrderTrigger` stores target, creation price, stop, take-profit, score, status and `created_at` (`models.py:168-187`). **Every past decision can be labeled after the fact from price history.** No new data collection is needed to start.

## Published memory gains shrink to noise out of sample

The literature offers large headline numbers and weak evidence behind them. FinMem reported 61.78% cumulative return on TSLA over about six months against −18.63% buy-and-hold. It never compared memory on vs off, and its top-K ablation was non-monotonic: K=3 did worse than K=1 ([FinMem](https://arxiv.org/pdf/2311.13743)). FinCon's belief-update ablation took GOOG from −11.94% to +25.08%, after four training episodes over one in-sample window ([FinCon](https://arxiv.org/pdf/2407.06567)). TradingAgents reported a Sharpe of 8.21 on AAPL over three months, with no memory ablation ([TradingAgents](https://arxiv.org/pdf/2412.20138)). The re-tests are sobering. Run past GPT-4o's October 2023 cutoff, in a window where the market returned about the same as before, **FinMem's total return fell 71.85% and TradingAgents' Sharpe fell 55.68%** ([Profit Mirage](https://arxiv.org/html/2510.07920v1)). Over 20 years and 100+ symbols, earlier LLM advantages "deteriorate significantly" ([FINSABER](https://arxiv.org/abs/2505.07078)). With tickers and dates masked, agent returns are "largely explained by passive market and style exposure" ([KTD-Fin](https://arxiv.org/abs/2605.28359)).

The single rigorous closed-loop ablation found memory and reflection return-neutral. CLQT measured run-to-run Sharpe noise of **±0.42 (1σ)**. Removing memory changed Sharpe by +0.52 and removing reflection by +0.09, both within noise. The authors kept memory only as a "strategy-consistency signal" ([CLQT](https://arxiv.org/pdf/2606.29771)). Practitioner experience adds a warning. One trader's similarity retrieval returned 5 of 5 winners from a store that held 3 losses, and the agent's profit factor fell from 2.42 to 0.94. The sample was tiny (6–7 trades), but the mechanism is clear: winners cluster in common conditions, so similarity search over-recalls them ([TradeMemory post](https://dev.to/mnemox/i-gave-my-trading-agent-memory-and-it-made-everything-worse-28a3)). TradingAgents, the most-used open-source system, removed its BM25 situation memory as "dead" plumbing. It fixed a bug where empty memory produced fabricated past lessons, and replaced the memory with an append-only decision log. Each decision there settles only after a five-day window, as raw return plus alpha against a benchmark, scored from the first close after the decision ([TradingAgents changelog](https://github.com/TauricResearch/TradingAgents/blob/main/CHANGELOG.md)).

Three lessons transfer to this bot. First, **numbers should carry the learning and text should only explain it**. "Language confidence is not tradable probability," and calibration belongs in an independent numeric module ([Alpha Illusion](https://arxiv.org/abs/2605.16895)). LLM self-correction without external signal often fails ([Huang et al.](https://arxiv.org/abs/2310.01798)). Second, the retrieval key should be the setup, not the name. Indicator-state retrieval beat text-embedding retrieval by 2 to 11 points of directional accuracy, roughly 500× faster ([META](https://arxiv.org/html/2609.28771)). Ticker strings invite recall of memorized company stories ([KTD-Fin](https://arxiv.org/abs/2605.28359)). For this bot the natural key is trigger type × regime × score bucket × market, with ticker secondary. Third, outcomes need time integrity: hide each outcome until it is observable, an "outcome embargo" ([Agentic Trading survey](https://arxiv.org/html/2605.19337v1)). Even so, nobody has shown a memory design that raises out-of-sample, cost-aware equity returns. EU equities are absent from the literature entirely. The honest prior for any change below is "small or zero, until measured."

## Seven changes ranked by P&L impact per unit of effort

The ranking puts the loop-closing enablers first, because nothing after them can be measured or learned without them. Next come cheap fixes that stop the learner from destroying value. Edge-seeking changes come last, since they carry the most overfitting risk. Effort assumes this codebase: S is a day or two, M is under a week. Impact is qualitative, because no production database was available. That gap is the reason the first two items come first.

| Rank | Change | Where | Effort | Expected P&L effect |
|---|---|---|---|---|
| 1 | Link decision to outcome: `report_id` on `OrderTrigger`, `Position`, `Trade`; store initial stop (1R) and entry snapshot; carry score onto SELL; post-mortem uses the linked report | `models.py`, `_run_migrations` in `src/db/session.py`, `jobs.py:347-359`, `paper.py`/`live.py` fills, `learner.py:48-69` | S | Enabler. Fixes calibration misattribution today |
| 2 | Daily outcome labeler for every `AnalysisReport` and expired or cancelled trigger: triple-barrier (own stop −1R, own target, else return at H days), after fees, benchmark-relative, with `observable_at` | New table plus one scheduler job; prices via `src/data/market.py`, fees via `fees.py` | S–M | Enabler. Adds labels for HOLDs and misses; several times more observations than fills |
| 3 | Make the learner statistically honest: expectancy in R, not win rate; a CI-based trigger instead of a 2-loss streak; one parameter per calibration; log each calibration as a trial | `learner.py:247-459` | S | Harm reduction. Stops threshold churn on noise |
| 4 | Post-mortems on live sells, `is_live` on `TradeLesson`, mode filter on prompt lessons and recap. Keep live auto-calibration off until item 6 proves out | `live.py` sell path, `models.py:189-204`, `learner.py:609-613`, `cold_start.py:256-302` | S | Small. Stops paper noise steering live prompts |
| 5 | Replace the loadout with a numeric track-record block: per-setup-bucket n, win rate, mean R with a shrinkage interval, losses always shown; empty when n < 30; drop the same-ticker L2 scenario and own-verdict atom; skip loadout building when no LLM is active | `cold_start.py`, `committee.py:59-116` | M | Candidate edge, LLM path only. Removes self-anchoring |
| 6 | Bounded numeric gate: shift `TRIGGER_MIN_SCORE` or size per bucket from Beta-Binomial or empirical-Bayes posteriors, within hard caps | `trigger_gate.py`, `risk.py` (live-money-safety review) | M | Largest potential. Works on the rules path too. Highest overfit risk; needs ~100 labels per bucket |
| 7 | Hygiene: scheduled prune; fix the € mislabel, phantom triggers and default-75 score; separate the proxy namespace; keep task references with error logging | `extractor.py`, `client.py`, `proxy.py`, `jobs.py` | S | Small. Cleaner LLM input; fewer wasted broker calls |

Item 1 is the smallest change that closes the decision→outcome loop. It is a handful of nullable columns, each with a migration entry, as CLAUDE.md requires. The report id is threaded from `jobs.py:297-313`, where the report is persisted, into `create_price_trigger` and on to the fill. The learner then reads the linked report instead of the newest one. Item 2 turns that linkage into labels. It also fixes the one-sided memory problem by labeling the trades the bot did *not* take. The label must use only bars after `created_at`, and it must not be visible to memory before its horizon ends. These are the time-integrity rules the critiques single out as the strongest-evidenced practice ([Profit Mirage](https://arxiv.org/html/2510.07920v1); [Agentic Trading survey](https://arxiv.org/html/2605.19337v1)). Benchmark-relative labels against SPY for US names and a STOXX or DAX index for EU names stop the loop from learning beta.

Item 3 earns its high rank because the current learner probably costs money. It tightens thresholds after two consecutive losses or a win rate under 40% over 20 trades. It loosens them at a win rate of 70% or more. The LLM calibrator may move nine parameters at once within wide clamps (`learner.py:360-370, 415-437`). At a 50% win rate, a two-loss streak follows any given point 25% of the time; at 40%, 36%. The rule therefore toggles on noise. It then fights `decay_idle_thresholds`, which lowers thresholds again after seven idle days (`learner.py:516-601`), so the two can oscillate. Nine free parameters fitted on 20 noisy outcomes is textbook overfitting. The weights it tunes affect only the rules fallback (`committee.py:84-88, 181`). Switching the signal to mean R with a confidence interval, requiring the interval to exclude zero before moving anything, and limiting each calibration to one parameter are all edits inside one file.

Items 5 and 6 are where gains, if any, come from. They differ in reach. Item 5 acts only when the LLM answers, and only as a nudge to its 0–100 score. Its main justified benefit is removing the self-anchoring and boilerplate that dominate the prompt today. Item 6 acts on every decision, rules path included, by turning settled per-setup outcomes into bounded threshold or size changes. That makes it the "independent calibration module" the critiques recommend ([Alpha Illusion](https://arxiv.org/abs/2605.16895)). It sits on the real-money path, so it needs the `live-money-safety` review. It should run paper-only until item 6's own A/B clears the promotion gate below. Changes ranked out of scope: embedding or similarity retrieval, re-enabling the LLM extractor, layered FinMem-style memory, free-text reflection lessons and anything in the code graph. Each adds complexity with the weakest out-of-sample support or none at all ([CLQT](https://arxiv.org/pdf/2606.29771); [FinMem](https://arxiv.org/pdf/2311.13743)).

## Proving a gain takes hundreds of paired decisions, not a month of trades

The current shadows cannot test memory. Every shadow consumes the same committee report, which was produced with memory on (`shadow.py:336-406`; call sites `jobs.py:380-382, 650`). `ShadowStrategy` varies only post-verdict entry, exit and sizing rules (`shadow.py:61-81`). And the `backtest-discipline` skill rules out historical replay, because LLM verdicts "cannot be replayed honestly on past data" (`.claude/skills/backtest-discipline/SKILL.md:31`). The only valid test is forward and paired. Add a `use_memory` (or `memory_mode`) flag to `evaluate_ticker`. It skips the loadout and learning context, and it skips `log_interaction`, so the counterfactual arm never writes into memory (`committee.py:59-73, 234-243`). Call `evaluate_ticker` a second time on the same data snapshot with memory off, only when the first call's `score_source == "llm"`; on the rules path both arms are identical by construction. Add a `report_variant` field to `ShadowStrategy`, so a `baseline` shadow and a `baseline_nomem` shadow differ only in the verdict they follow. Persist both verdicts with an arm tag. Run two memory-on arms against each other for about two weeks first. That A/A phase measures how often the nondeterministic LLM disagrees with itself; any A/B difference must clear that floor. The cost is double committee LLM calls per candidate, under the existing 300 s evaluation timeout (`jobs.py:296-298`).

Score the experiment at the decision level, not the portfolio level. Sessions evaluate at most four candidates each (`jobs.py:280-283`), and closed trades likely number in the tens per month. Item 2's labels give every BUY verdict in both arms an R outcome, free of fills, cash competition and slot path-dependence. The sample sizes below are the analysts' own calculations from the standard two-sample formula (α = 0.05 two-sided, 80% power) ([MedCalc](https://www.medcalc.org/manual/sample-size-comparison-of-proportions.php)). The planning per-trade SD of 1.0–1.5R assumes the default ~2:1 target; it is not a measured value from this bot.

| Design | Effect to detect | Per-decision SD | Required n |
|---|---|---|---|
| Two independent arms | +0.2R mean | 1.0R / 1.25R / 1.5R | 392 / 613 / 883 per arm |
| Two independent arms | +0.1R mean | 1.5R | 3,532 per arm |
| Paired, same candidates, ρ = 0.5 | +0.2R mean | 1.5R | 441 pairs |
| Paired, same candidates, ρ = 0.8 | +0.2R mean | 1.5R | 177 pairs |
| Two arms | +5 pp win rate (50→55%) | — | ~1,565 per arm |
| One arm, edge > 0 (MinTRL, 95%) | +0.2R mean | 1.5R | ~155 trades |

Win rate is the wrong primary metric: it needs about four times the sample of a mean-R test, and it ignores payoff size. The primary metric should be the paired difference in mean R per BUY decision, after fees, at a fixed horizon, with a bootstrap CI clustered by ticker and day. Secondary metrics are the shadow-portfolio figures the skill requires: total return, max drawdown, Sharpe and Sortino, trade count, fees and benchmark (`SKILL.md:27-28`). Results under about 30 trades are noise and must be reported as such (`SKILL.md:30`). Fix the sample size and stop date before starting. Checking weekly and stopping at the first p < 0.05 inflates false positives.

Every variant counts as a trial: each memory tweak, prompt change, learner rule and each automatic calibration. Keep a ledger. Without that count, a backtest is "worthless" ([Deflated Sharpe Ratio](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf)). Deflate the winner by the ledger count, or demand t ≥ 3 rather than 2 ([Harvey, Liu & Zhu](https://nber.org/papers/w20592)). The promotion gate follows from that. The CI must exclude zero. The t ≥ 3 or DSR > 0.95 hurdle must be met. The result must not reverse in any regime split; split by the index-above-SMA flag already used by shadows (`shadow.py:269-273`). Drawdown must be no worse than the frozen `baseline` control. Pass that gate on paper, then go through the `live-money-safety` review, and only then go live.

### Every memory loop can teach the bot to chase noise

The risks are concrete. **Small-sample poisoning:** a lesson distilled from three trades, shown without n, reads as established fact. Hence item 5's "empty below n = 30" rule, and the need for roughly 100 labels per bucket before a ±5-point win-rate estimate means anything. **Confirmation loops:** winners cluster in common setups, so any anecdote retrieval over-recalls them ([TradeMemory post](https://dev.to/mnemox/i-gave-my-trading-agent-memory-and-it-made-everything-worse-28a3)). Re-injecting "we said BUY on X last time" anchors new verdicts on old ones. Measure this directly: compare how often repeat evaluations of the same ticker flip in each arm. **Hindsight leakage:** an outcome injected before its window settles is look-ahead. FinMem's training reflections were written while seeing next-day labels ([FinMem](https://arxiv.org/pdf/2311.13743)). **Regime shift:** lessons learned in a bull market mislead in a bear market. LLM agents already run too conservative in bulls and too aggressive in bears ([FINSABER](https://arxiv.org/abs/2505.07078)). Tag every label with its regime, and down-weight labels older than one regime. **Fabricated memory:** an empty block must render as nothing, not as an invitation to invent lessons ([TradingAgents changelog](https://github.com/TauricResearch/TradingAgents/blob/main/CHANGELOG.md)). **Live-money exposure:** items 4 and 6 touch the real-money path. Automatic live calibration should stay off until a paper A/B has proved that calibration itself helps. One risk cancels out: pretraining knowledge of large-cap names biases both arms of a concurrent A/B equally, so the paired difference stays clean. It would not stay clean against a rules-only baseline ([Glasserman & Lin](https://arxiv.org/abs/2309.17322)).

## Conclusion

The question "how do we make memory produce gains" turns out to be mostly "how do we let the bot see its own results." Today memory, the learner, shadows and the review tracker each hold a piece of the decision→outcome story, and nothing joins them. The parts that change numbers learn from the noisiest, most selected slice of data: the last 20 paper fills. The cheapest gains are therefore subtractive and structural. Link reports to fills, label every decision including the ones not taken, stop the learner reacting to two-trade streaks, and stop feeding the LLM its own last opinion. These changes are small, safe on paper, and make every later claim testable.

The literature's verdict is that memory is a discipline tool, not an alpha source. That reframes the goal: memory should earn its place by measurably cutting bad entries in setups that keep losing, not by finding new winners. Two unknowns decide how much any of this is worth. The first is the share of committee verdicts that actually come from the LLM. The second is the bot's real per-decision R distribution. Both can be read from the owner's database in an afternoon, and they should be read before the first line of item 5 or 6 is written. If the LLM path turns out to be rare, prompt-side memory is close to irrelevant. Then the numeric gate in item 6, fed by item 2's labels, is the only route by which "memory" can move P&L at all.
